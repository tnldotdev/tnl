# error audit

The follow-up stack reviews first-party failure production, classification,
cause identity, retry decisions, and output boundaries across `tnl` and
`tnl.dev`. The inventory below records the owner and disposition, including
internal errors that are intentionally adapted later. It is a snapshot of this
audit; [failure boundaries](errors.md) describes how to add future errors.
