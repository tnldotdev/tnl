# service behavior and product decisions

This document describes what a developer should be able to expect from `tnl`.
It separates basic correctness, approved product decisions, and choices still
awaiting review.
It also explains what changed from the old public URL system, whether the change
looks worthwhile, and what is still broken, surprising, or insufficiently tested.

Judge the behavior by what we want the product to do. The old code and tests
help explain the changes; they do not set the requirements.

## what we decided

These are the decisions from the follow-up. Some need code changes; others need

[work tracker](https://md.cormo-turtle.ts.net/.worktree/tnl/public-url-guarantees-audit-9fb7a7c1/service-review-work.md)

### configuration examples

The new settings will look like this. They are not implemented yet.

```ts
import { defineConfig } from "@tnldotdev/tnl/config";

export default defineConfig({
  services: { web: {} },
  deployments: {
    local: {
      targets: {
        web: {
          public: true,
          http: {
            requestBodyIdleTimeout: "30s",
          },
        },
      },
    },
  },
});
```

The outage setting belongs to the server operator, not each app:

```yaml
version: 1
tnld:
  control_outage_tolerance: 5m
```

The equivalent environment variable is
`TNLD_CONTROL_OUTAGE_TOLERANCE=5m`; the flag is
`--control-outage-tolerance=5m`. Control supplies the serving deadlines to the
other components. Five minutes is an availability-versus-revocation choice,
**not a measured performance threshold or five extra minutes after an outage
is detected**. During a partition, a newly revoked permission can remain usable
for the remaining allowance, never beyond an earlier credential/service expiry.

### ideas we dropped

| Earlier proposal                                                                      | Final decision                                                                                              |
| ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Single selected webhook receiver by default                                           | Keep synchronous fanout and selected delivery where one response is needed.                                 |
| Track successful recipients across provider retries; add exponential delivery backoff | Not part of the simple webhook cleanup. Provider retries can redeliver to previously successful recipients. |
| Acknowledge stored webhooks immediately and deliver through a SQLite outbox           | Deferred. Do not add a queue or promise durable background delivery.                                        |
| Feedback sign-in as merely a default, retaining an anonymous option now               | Require sign-in; anonymous feedback is deferred.                                                            |
| Telemetry opt-in                                                                      | Rejected: telemetry must default on and be opt-out.                                                         |
| Fixed total upload time, plus another optional duration knob                          | One body-idle setting for now; no additional total-upload-duration setting.                                 |
| Preserve omitted configuration restrictions through merge/explicit-clear semantics    | Replace configuration; omission returns to defaults. Retain independent conflict checks.                    |
| Drain deadline followed by potentially unbounded cleanup                              | One bounded shutdown budget with honest timeout/cleanup reporting.                                          |
| Two-minute control-outage allowance                                                   | Five-minute default, server-configurable.                                                                   |

## a few terms used throughout

| Term             | Plain meaning                                                                                                                                   |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Service          | The saved record for an app or other listener. It can survive app restarts.                                                                     |
| Service run      | One attempt to serve that saved service. A later attempt has a new run identity and number.                                                     |
| Public endpoint  | The hostname and port a visitor uses through the public server. Being public does not mean anonymous visitors are allowed.                      |
| Connector access | Reaching a service through a local `tnl` connector rather than through its public endpoint.                                                     |
| Publisher        | The running native `tnl` process that carries traffic to the app.                                                                               |
| Control          | The server component that stores services, checks permissions, and assigns work.                                                                |
| Ingress / relay  | Server components that accept public connections and carry them to a publisher. They are not the application.                                   |
| Ready            | A word that must be qualified: a listener can be registered, connected, publicly reachable, or successfully checked. Those are different facts. |

The old code had **both** public URL records and a separate service system.
The new code uses services for both public and connector access. In particular,
old workload credentials already applied to services—not to the old public URL
record type. Supporting public service access now does not require bringing that
old record type back.

## the most important findings

### problems and contract choices

These are the five distinct source findings behind several of the old
“unmet” entries. They should not all be treated the same way.

| Finding                                                             | What happens                                                                                                                                                                                          | My assessment                                                                                                                                                                                                  | What I recommend                                                                                                                                 |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Upload timeout is accidentally cleared                              | On the first HTTP/1 application request, accepting the connection clears the deadline that was supposed to stop an unfinished upload. The isolated timeout tests do not include this acceptance step. | **Implementation fault.** Old code preserved the deadline, but its fixed total-upload policy is also changing.                                                                                                 | W01 must fix the interaction and implement the approved idle policy in **P33**. Evidence: G054, G247.                                            |
| Stopping an already-stopped run can fail after suspension           | The close operation checks that the saved service is enabled before it confirms that the exact run was already closed.                                                                                | **Cleanup fault.** Suspension should prevent new service, not prevent safe confirmation that old work has stopped.                                                                                             | Accept a valid, exact close retry without reopening anything. **C24**, P13. Evidence: G165.                                                      |
| Certificate polling happens earlier than the supplied time          | If control says to poll in 60 seconds, the publisher polls again after at most five seconds.                                                                                                          | **Worse default:** more control traffic with no demonstrated benefit. It is not evidence that the certificate authority is contacted too early. The meaning of the supplied time needs to be explicit.         | Treat it as “do not poll before this time,” unless the API explicitly says it is only a hint. **C15**, P96. Evidence: G190.                      |
| A stale configuration write can replace a newer one                 | Target and access-policy changes can share the same trust version. A caller may omit the separate configuration check and overwrite a later edit.                                                     | **A policy choice with a dangerous default**, not proof that unconditional replacement must never exist.                                                                                                       | Protect normal edits against lost updates. | Publisher authentication errors use 500 where the old path used 503 | A generic backend error reaches the internal-error response.                                                                                                                                          | **Not automatically a bug.** An unexpected server fault should be 500; a known temporary dependency outage should normally be 503. Blindly copying the old status for every backend error would also be wrong. | Specify and test the distinction. Do not infer a credential leak from this status difference. **C34**, P26. Evidence: G138.                      |

## basic correctness

These requirements do not decide whether a service should be public, whether
feedback should require sign-in, or how long a demo should last. They say that
**once we choose a policy, the implementation must obey it**.

“Supported” below means supported by inspected code/tests, not that this review
ran the tests. “Partial” means the relevant proof is missing or narrower than the
claim. Some requirements have both supported parts and a gap.

## product decisions for sign-off

These are choices that can reasonably differ between products. **Approved**
rows state the agreed target, contrast it with the audited code, and link work.
**Pending** rows retain recommendations for later review. An approved row is
not an implementation receipt. Original P IDs are preserved.

Assessment words:

| Assessment      | Meaning                                                                             |
| --------------- | ----------------------------------------------------------------------------------- |
| Better          | A useful improvement, subject to the stated safeguards.                             |
| Mixed           | There is a real benefit and a real cost or surprise.                                |
| Worse           | A reduced capability or poorer default without a demonstrated compensating benefit. |
| Keep            | The existing behavior is reasonable.                                                |
| Not established | The audit did not prove the complete user-visible behavior.                         |

## important missing tests

Missing evidence should lead to **the smallest useful test for the approved
behavior**, not automatic reconstruction of every old suite.

- A production operation should be exercised when the claim is about that
  operation. Directly touching its helper/table is weaker.

## appendix: test jargon in plain english

These definitions explain how the tests use the words. They do **not** promise
that every mentioned mechanism is part of the supported product.

### words with several different meanings

| Word in tests      | Why it is confusing                                                                                                          | Read it as                                                                                                     |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Authority          | Can mean permission, a credential issuer, DNS control, or trusted certificate roots.                                         | Ask **who may do what**, **who signed it**, or **which names/keys are trusted**. They are different questions. |
| Identity           | Can be a person, publisher, server process, device, workload, or browser identity.                                           | Check the specific identity type; proving one does not prove another.                                          |
| Owner              | Can mean saved-service owner, app-listener owner, local-process owner, installed-job owner, or DNS-record owner.             | Name the thing being owned. “Owner cleanup” alone is too vague.                                                |
| Session            | Can be a control login, browser session, share session, or a transport connection carrying many requests.                    | Do not infer login permission from a transport session or vice versa.                                          |
| Source             | Can be visitor IP, a credential source, Git/source state, or a configuration input.                                          | “Source is trusted” needs to say which source and for what purpose.                                            |
| Pool               | Can mean multiple publisher runs, pooled relay connections, target HTTP keep-alive connections, or an ingress-address group. | Check which resource is pooled and where its limits live.                                                      |
| Ready              | Can mean registered, connected, public endpoint usable, or an application check passed.                                      | Ask **ready for which operation**.                                                                             |
| Promotion          | Can mean accepting an HTTP connection into app capacity, or making a staged certificate current.                             | These are unrelated state changes with separate tests.                                                         |
| Replay             | Can mean unsafe reuse of a credential, a safe retry returning one saved result, or repeating an app request.                 | A “replay succeeds” test can be good or bad depending on which meaning applies.                                |
| Native             | Often means the compiled `tnl` process, its local API, or a protocol-specific client.                                        | It is not a third access path called “native access.” Public endpoint and connector access are separate.       |
| Route / public URL | Old test names sometimes retain these after the model changed.                                                               | Inspect whether the test now uses an ordinary service or merely kept its filename.                             |
| Shared             | Can mean team-owned, reused across runs, used by several HTTP streams, or visible to reviewers.                              | Sharing a resource does not imply shared permissions.                                                          |

| No replay                            | The tested layer does not automatically resend an ambiguous request. It is not exactly-once transaction execution.                    |
| Recovery episode / observation       | One period of unexpected connectivity loss / evidence that a visitor again received a publisher byte.                                 |

### certificates, DNS, and protected storage

| Term                                | Plain meaning                                                                                                                               |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| TLS termination                     | Where encrypted visitor TLS is decrypted and its certificate/key are used—here, at the publisher.                                           |
| Target trust                        | The roots/name/rules the publisher uses to verify the local target's separate TLS connection.                                               |
| CA / root / WebPKI                  | Certificate issuer / trusted signing root / public web certificate trust system. A local test CA is not public WebPKI evidence.             |
| CSR                                 | Certificate signing request: public key plus requested identities, signed by the corresponding private key.                                 |
| SAN                                 | Names or other identities listed in a certificate/request.                                                                                  |
| Wildcard / apex                     | A pattern such as `*.example.test` / `example.test` itself. The wildcard does not automatically cover the apex or deeper names.             |
| Certificate plan                    | The exact names, allowed sharing scope, cache identity, and challenge method approved for issuance.                                         |
| Cache scope                         | Which publisher/team/server/plan may share stored certificate material.                                                                     |
| Pending / staged / current material | Key/request waiting for issuance / returned certificate not yet promoted / acknowledged certificate selected for serving.                   |
| Install acknowledgment              | Control's confirmation for the consuming run, not merely proof that bytes reached a local cache.                                            |
| PEM / DER                           | Text-wrapped certificate/key encoding / binary encoding. A supplied parsed `Leaf` field is not trusted instead of the real bytes.           |
| EKU                                 | Certificate usage restriction, such as suitability for a TLS server.                                                                        |
| ACME                                | Certificate-authority protocol used to request and validate certificates.                                                                   |
| Account / order / authorization     | The CA account / one issuance request / proof that a requested name is controlled.                                                          |
| DNS-01                              | Proving name control by publishing a specified DNS TXT value.                                                                               |
| Finalization                        | Sending the approved request to finish issuance after name authorization.                                                                   |
| Retry-After / RetryAt               | A supplied retry time/delay. Its minimum-versus-hint meaning must be explicit.                                                              |
| Work lease                          | Temporary exclusive ownership of background issuance/cleanup work. It does not make remote provider calls part of one database transaction. |
| Uncertain finalization              | The CA may have issued a certificate, but local state does not yet know the result/lifetime. Safe release cannot assume nothing happened.   |
| TXT presentation                    | Publishing the DNS challenge value.                                                                                                         |
| Cleaning intent                     | Saved state saying challenge removal must occur, so retry/restart knows the cleanup is still owed.                                          |
| Change receipt / INSYNC             | Provider identifier for a DNS mutation / provider confirmation that it completed. A readable record list alone is not that confirmation.    |
| Owned record / ownership marker     | A DNS record/value tnl can identify as its own, rather than deleting arbitrary records at the same name.                                    |
| Authoritative / recursive resolver  | DNS server answering for the zone / resolver following/caching DNS answers on a client's behalf.                                            |
| TTL / negative caching              | Cache lifetime for an answer / for a missing-name answer. Neither guarantees every client behaves identically.                              |
| NS / SOA / A / AAAA / CNAME         | DNS delegation / zone metadata / IPv4 / IPv6 / alias records.                                                                               |
| Route 53 / Pebble                   | AWS DNS service / local ACME test server. An emulator or Pebble test is not a live AWS/public-CA test.                                      |
| Fsync / directory sync              | Ask the filesystem to persist file contents/name changes before handing out a key or reporting durable completion.                          |
| Inode / file identity               | Filesystem identity of the actual file; replacing it with same text can still mean lost trusted local authority.                            |
| Checkpoint / manifest               | Saved bookkeeping used to detect missing/replaced portions of protected identity/certificate state.                                         |
| Storage-key rotation                | Re-encrypting saved private data under a new storage key, not changing the service's signing identity by itself.                            |
| WAL                                 | Database write-ahead log; private text must not escape into it merely because the main database row is encrypted.                           |

### browser access, feedback, and SDKs

| Term                               | Plain meaning                                                                                                                                               |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OIDC                               | Login protocol establishing identity through an identity provider. It does not automatically grant app visitation.                                          |
| State / nonce / PKCE               | Separate values/checks binding a login exchange to its initiating browser/request and resisting code misuse.                                                |
| JWT / JTI / issuer / JWKS          | Signed-token format / token issuance ID / signer identity / published verification keys. A valid signature alone does not mean current permission.          |
| Host-bound cookie                  | Cookie/credential restricted to the intended hostname, not every service under a shared domain.                                                             |
| Handoff                            | Short-lived one-use transfer of browser/share access to the intended endpoint.                                                                              |
| Link secret / session secret       | Secret in the initial share link / later browser credential. They are not interchangeable.                                                                  |
| Fingerprint / digest               | One-way identifier for a secret or configuration, not the secret itself or encryption.                                                                      |
| CSRF / Origin check                | Preventing another site from making a state-changing browser request under the user's existing cookies. Port and scheme can matter.                         |
| Workload                           | Automated client whose identity is proved by a supported signed provider assertion rather than human sign-in.                                               |
| Provider proof / hard cap          | Evidence the provider identity is currently valid / an independently fixed maximum session end time.                                                        |
| Registered key / device identity   | Other explicitly authorized machine-key visitor identities—not arbitrary possession of a public key.                                                        |
| Preview / share                    | Saved group of services / expiring access to the captured service set. A preview edit need not expand an existing share.                                    |
| Feedback report / thread / event   | Immutable first submission / whole conversation / later reply, source update, or status change.                                                             |
| Verified author                    | Identity confirmed from authenticated browser/implementer facts, not a submitted name or a share's subject.                                                 |
| Source state / Git blob            | Project-relative Git/content identifiers / identifier for file contents. Not uploaded source text.                                                          |
| Complete / inconclusive            | Enough comparable data was captured / the comparison cannot safely say match or mismatch.                                                                   |
| Cursor / watermark                 | Position after which to resume history / fixed upper bound for one consistent history read.                                                                 |
| Pin / anchor                       | A thread's on-page marker / saved description of the element or text selection to find again.                                                               |
| Shadow DOM                         | Toolbar UI/style isolation inside the page. It is not protection from a hostile application page.                                                           |
| CSP / nonce / ETag                 | Browser content-security rules / approved per-response script marker / cached-response identity. Injection must not silently break their meaning.           |
| App registration                   | A currently owned listener reported by the app, distinct from its saved service and publication run.                                                        |
| Prepare / register / observe       | Reserve/evaluate app selection / report an actual listener / receive status or authorized observation. Observe must not accept app-invented health success. |
| Port zero / post-bind              | Ask the OS for a free port / inspect the actual chosen address after binding.                                                                               |
| App-owned / SDK-owned listener     | Server supplied by the application / server the SDK created and must shut down.                                                                             |
| ASGI lifespan / Uvicorn worker     | Python startup/shutdown protocol / actual serving process, distinct from a reload supervisor.                                                               |
| HMR                                | Hot module replacement: framework code updates over a live development connection. Local HMR is not automatically public-tunnel HMR.                        |
| Installed registry / runtime epoch | Protected saved job definitions and keys / one particular running job owner.                                                                                |
| Outbox / acknowledgment            | Saved telemetry events awaiting delivery / confirmation allowing queued data to be removed.                                                                 |
| Preference epoch                   | Version fencing events/requests collected under an earlier telemetry preference.                                                                            |

### what the tests actually prove

| Term or test style                        | Plain meaning and limitation                                                                                                                                                    |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unit test                                 | Exercises a small owner/function. Its fake dependencies do not prove full server wiring.                                                                                        |
| White-box test                            | Can inspect or manipulate private implementation state. Useful, but may bypass the public operation being claimed.                                                              |
| Fixture                                   | The test setup. Inspect it to see which components are real and which facts were supplied manually.                                                                             |
| Fake / stub / mock / scripted server      | Replacement dependency with controlled responses. A response saying Ready does not prove an actual publication became ready.                                                    |
| `httptest.ResponseRecorder`               | An in-memory HTTP response collector, not a real client/socket. It cannot prove final network-byte ordering.                                                                    |
| `net.Pipe`                                | An in-memory connected byte stream. Real protocol bytes can cross it, but it is not real TCP/network timing.                                                                    |
| Wire test                                 | Real protocol bytes/handshakes are exchanged. The authority or remote server may still be fake.                                                                                 |
| Composition test                          | Checks that real components are wired together. Read which boundaries remain substituted.                                                                                       |
| PG / state integration                    | Uses real PostgreSQL/transactions; may directly stage readiness/certificates and never send visitor traffic.                                                                    |
| Native IPC test                           | SDK talks to the local native process/API. This alone does not mean a public visitor reached the app.                                                                           |
| Runtime integration                       | Real server-role/publisher composition and network/state boundaries, often with local CA/DNS fixtures. Roles may still be goroutines in one process.                            |
| Built-binary test                         | Runs compiled executables as processes. Stronger process-start/CLI evidence, not automatically live production infrastructure.                                                  |
| DOM / browser test                        | Simulated document model / real browser. Both can still use a fake API and direct local URL.                                                                                    |
| `synctest` / fake clock                   | Deterministic simulated time. Five simulated minutes are not five minutes of demonstrated production performance.                                                               |
| Barrier / gate / channel handshake        | Test synchronization proving a particular ordering without hoping a sleep caused a race.                                                                                        |
| Race detector                             | Finds certain unsafe concurrent memory accesses. Passing it does not prove the access policy, protocol, or cleanup contract is correct.                                         |
| Injected stall / blackhole / process kill | Deliberately blocked dependency / dropped network traffic / abruptly stopped process. They test different failure boundaries.                                                   |
| Cold first POST                           | The first request uses a fresh connection and sends a real body. A warmed GET followed by a POST is weaker startup evidence.                                                    |
| Opt-in tier / Task selector               | A deliberately selected test class/command, often requiring databases, containers, DNS, load, or credentials. A skipped tier is not a pass.                                     |
| Load test / benchmark                     | A defined workload or measurement harness. Its existence does not establish an achieved performance number.                                                                     |
| Offered load                              | Requests the test tried to schedule, not merely the ones it completed.                                                                                                          |
| p50 / p95 / p99                           | Median / 95th / 99th percentile of the measured samples. If samples exclude failures, they do not summarize failure latency.                                                    |
| SLO                                       | A promised service-level target. A local timeout assertion or logged percentile is not automatically one.                                                                       |
| Fuzz test / golden fixture                | Generated malformed/unusual inputs / saved expected wire bytes or output. Neither replaces a complete user workflow.                                                            |
| Independent assertion                     | Measures the claimed result through another meaningful boundary—for example real app bytes or a recount of underlying rows—not just a helper repeating its own expected answer. |
