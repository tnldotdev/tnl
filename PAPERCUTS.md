# Papercuts

- `task go:test-integration` intermittently failed while starting `TestIntegrationRelayDrainPreservesActiveVisitorStream` because the certificate worker lost its ACME work lease; three immediate isolated race-detector reruns passed, suggesting a startup timing flake.
- A rolling standalone deployment can delay the new ingress lease past its first usage tick; rejected idle watermarks must be regenerated or the process retries a pre-registration timestamp forever.
- The Linux binary split-publish check intermittently outlived QUIC's 30-second default idle timeout during certificate provisioning because publisher connections sent no keepalives, closing both sessions before readiness.
- An externally terminated `task go:test-integration-dns-linux` invocation left its disposable PostgreSQL container and network behind despite the shell cleanup trap; interrupted runs need an explicit Docker cleanup check.
- `TestControllerInstallsCertificateBeforeReady` observed the certificate callback before the controller recorded its validity, so the race suite could assert readiness before the controller goroutine completed the transition.
- `flyctl` is configured in the `tnl.dev` mise environment but not `tnl`, so staging deploy commands launched from the product repository need the `tnl.dev` tool environment explicitly.
- A QUIC listener test closed the client before the server's `Accept` completed and could hang until the Go test timeout under race instrumentation; synchronize acceptance before closing either side. The test-file split reintroduced this ordering bug, producing a five-second acceptance timeout in Linux race CI.
- `task format-check` reports unchanged `cmd/tnlbench/plan.go` from `goimports -l`, so a clean wording-only change cannot pass the repository formatting check without touching unrelated benchmark code.
- A fresh Git worktree has no ignored `node_modules`, so `task generate` fails loading `json-schema-to-typescript` until the lockfile dependencies are installed in that worktree.
- Restoring the completed-usage-bucket regression test exposed a reverted SQL finalization fix in the combined refactor: complete deliveries retained their last report timestamp instead of advancing `observed_through` to the bucket end. Restore the query source and regenerate sqlc output together.
- Integration CI exposed two test-only assumptions hidden by routine runs: PostgreSQL could not infer one timestamp parameter across direct values and interval arithmetic, while `reflect.DeepEqual` distinguished equal timestamps returned with different location metadata.
- `flyctl deploy --build-only` tried to derive configuration from existing Machines when the new benchmark app had none, failing before the image build; build-only deploys need an explicit local app config.
- Fly failed to start a benchmark Machine from tested PostgreSQL 17 and 18 images, then rejected both Compose's `tag@digest` form and the resolved canonical digest as an invalid image identifier; use Fly Managed Postgres instead of relying on external-image Machine launches.
- `flyctl mpg list --json` reports zero disk for v2 clusters; use `flyctl mpg status --json` when cleanup must validate provisioned storage.
- Running `task lint` and `task test` concurrently made the output-pipe resource test miss its three-second poll timeout; an immediate isolated rerun passed, so full JavaScript builds should not compete during this timing-sensitive test.
- A Fly smoke run queried new benchmark hostnames before Route 53 changes propagated, causing the recursive resolver to retain NXDOMAIN after the records existed; query the authoritative name servers directly before the first public lookup.
- The benchmark's least-privilege Route 53 user cannot call `GetChange`, so using the SDK propagation waiter also blocked cleanup; DNS readiness must not expand cleanup permissions.
- Dialing a Route 53 name-server hostname from Go selected its IPv6 address even though this host had no IPv6 route; resolve the authoritative server's IPv4 address first so direct DNS probes do not fail through the tailnet resolver.
- Passing `--autostop off` to `flyctl machine run` treated `off` as a positional command argument, so `tnld` received `serve off` and exited; optional-value flags must use the unambiguous `--autostop=off` form.
- Fetching `origin/main` before saving the webhook plan failed because the 1Password SSH agent could not sign the authentication request; restore or approve agent access before retrying Git operations that need authentication.
- The Homebrew `pscale` binary hung without output even for version and help commands; pinning `aqua:planetscale/cli` in mise restored the CLI, though macOS Keychain delayed the device-login prompt for roughly 45 seconds.
- PlanetScale authentication and SKU preflight succeeded, but database creation failed before provisioning because the organization could not verify its credit card; billing must be fixed before retrying the same benchmark plan.
- The benchmark preflight uses the AWS Go SDK, but the pinned toolchain does not provide the `aws` CLI and the least-privilege benchmark user cannot call `ListHostedZones`, so ad hoc global Route 53 cleanup listings are intentionally unavailable.
