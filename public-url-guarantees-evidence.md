## how to read the service-based review

Each stable ID has its old statement/evidence in the inventory and its current
implementation/test evidence in the verdict table. Read both together:

| Status   | Meaning                                                                                                                                                           |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Met      | The new implementation and relevant assertions support the old guarantee. Execution receipts are recorded separately.                                             |
| Changed  | The new system deliberately or observably behaves differently. This is not automatically an improvement or an accepted change.                                    |
| Unmet    | A concrete implementation path violates the stated requirement. Inherited limits and baseline overclaims are explicitly distinguished from migration regressions. |
| Unproved | Evidence is missing, weaker, or indirect. This does not by itself establish a production defect.                                                                  |

Do not mark a guarantee met just because a similarly named test exists, a helper
returns the desired value, or the new system checks a database row without
exercising the old delivered-byte or cleanup boundary.

### saved identity and management

Evidence: `internal/publisher/publisher_test.go:20–242`,
`internal/control/api/public/public_urls_test.go:188–257`, and
`internal/control/state/public_urls_integration_test.go:18–261`.

- **G001:** Repeating a durable publication selects the existing exact hostname
  and saved public URL, rather than allocating a replacement.
- **G002:** A publisher's serving client does not implicitly have management
  authority to create or update a public URL.
- **G003:** Reuse must match the saved team, domain, membership/scope, purpose,
  and lifecycle; a hostname match alone cannot adopt another owner's resource.
- **G004:** A suspended saved public URL remains discoverable for management but
  cannot silently be recreated or resumed by ordinary publication.
- **G005:** Ephemeral publication does not reuse an unrelated saved ephemeral
  public URL.
- **G006:** An unavailable, unauthenticated, or invalid lookup response does not
  trigger a speculative create.
- **G007:** Canonically equivalent retry inputs recover the original result;
  changed intent under an existing idempotency key conflicts.
- **G008:** Updates use the expected mutation revision; stale updates do not
  replace newer target or policy settings.
- **G009:** Public URL mutation handlers authenticate before looking up the
  requested resource and do not reveal resources outside current authority.
- **G010:** Ordinary users and administrators cannot claim reserved managed root
  names or bypass member namespace ownership.
- **G011:** Nested member hostnames retain their original membership ownership.
- **G012:** IP policies with 512 prefixes can be persisted, reloaded unchanged,
  and updated to 511 prefixes. The old HTTP handler also accepts 4,096-prefix
  requests; that handler test alone is not a real-database proof at that size.

### publisher HTTP, policy, payloads, and limits

Evidence: `internal/publisher/public_url_server_test.go`,
`internal/publisher/public_http_guard_test.go`,
`internal/publisher/public_url_limits_test.go`,
`internal/publisher/public_url_streaming_test.go`,
`internal/publisher/public_capacity_test.go`,
`internal/publisher/public_capacity_retirement_test.go`, and
`internal/publisher/proxy/proxy_test.go`.

- **G046:** Visitor TLS ends at the publisher. Admission to a relay is not
  authorization to call the application.
- **G047:** HTTP Host and TLS SNI must name the intended public URL, including
  when sibling names share a certificate. The old hostname comparison discards
  a valid explicit port; it does not require exact `hostname:443` authority.
- **G048:** Source forwarding headers are replaced with accepted visitor facts;
  application paths and credentials are not repurposed as tnl authority.
- **G049:** Each application request needs current visitor permission; a
  previously authorized connection is not a permanent permission cache.
- **G050:** Streaming requests and WebSockets remain bound to their permission
  source and limiting parent authority and are interrupted on revocation without
  replay. Same-source background renewal can extend a renewable token deadline;
  unrelated replacement credentials cannot extend the original request.
- **G051:** Revoking one permission does not unnecessarily terminate an
  unrelated HTTP/2 stream or the entire shared TLS connection.
- **G052:** A later permission replacement authorizes future requests; it does
  not retroactively extend an already-running request.
- **G053:** HTTP/1 and HTTP/2 preserve streaming upload bytes and trailers,
  permit an early response before upload EOF, and preserve application auth.
- **G054:** Incomplete or trickling request bodies are bounded, but a completed
  request body does not impose that upload deadline on a long response.
- **G055:** Truncated target responses are not falsely reported to visitors as
  clean successful completion.
- **G056:** Request total, concurrency, and rate limits apply after visitor
  authorization and are shared across visitor connections for one run.
- **G057:** An admitted final response finishes before its total-budget
  completion signal; denied or failed promotion does not spend application work
  as though the target ran.
- **G058:** Physical connection capacity is charged once per connection, not
  once per HTTP request. An idle admitted connection still owns its slot.
- **G059:** Pending, source, relay, and run capacity remain separate so one
  slow source or relay cannot consume all admission room.
- **G060:** Capacity is not reusable until physical connection cleanup,
  entered request handlers, and owned decision work join.
- **G061:** Concurrent close, cancellation, and drain close the physical
  visitor once, preserve independent failures, and do not restart the original
  drain deadline.

## evidence limits from the runtime audit

- Runtime integration uses production role composition and real network/SQL
  boundaries, but generally runs roles in goroutines with local CA/DNS/OIDC
  fixtures and accelerated renewals. Built-binary tests are a separate tier.
- No numerical production latency, memory, throughput, recovery-time, or capacity
  promise follows from an opt-in load-test definition. The baseline audit found
  no retained measurement results establishing one.
- “No replay” means the tested forwarding or response-loss path did not repeat
  application work. It does not mean exactly-once application transactions or
  protection from caller-initiated retries.
- Short control-outage evidence requires recovery before existing process leases
  expire. It is not indefinite outage availability.
- Public workload HTTP does not yet have an identified baseline proof retaining
  one original request through repeated 90-second lease renewal and provider
  proof replacement during control failure. Connector-path lease tests are not
  interchangeable with that public HTTP proof.
- Guest privacy tests explicitly delete resources or invoke advanced-clock
  cleanup. They do not prove that every secret is deleted exactly 72 hours after
  creation without maintenance scheduling delay.
