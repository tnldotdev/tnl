### What changed

- When a visitor connection closes, ingress and the relay can show the last
  completed step and whether any publisher bytes reached ingress. For a probe
  that fails during TLS, use `client_hello_id` to find its ingress record. Use
  `visitor_connection_id` to follow it through the relay and publisher.
- If control returns a publisher watch `503`, look up the response's `request_id`
  in `request_ids`. The batch log distinguishes time spent getting a database
  connection from time spent running the comparison.
- Logs show when a publisher connection drops, an ingress lease expires, or
  routing goes stale. Routine visits add no log lines. Repeated failures are
  sampled, and `tnl_diagnostic_samples_total` counts suppressed samples.
- The Keepalive ramp Worker reports which attempts stalled during discovery,
  while waiting for headers, or while reading or checking an asset body. This
  does not enable those logs on the production Keepalive Worker.

### Upgrade from rc.49

This release adds no PostgreSQL or client SQLite migrations. It does not change
HTTP API or tunnel wire formats. No new settings are required.
