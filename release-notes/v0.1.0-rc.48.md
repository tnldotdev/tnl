## Faster DNS for new publisher addresses

- For a public HTTP deployment binding in a tnl-managed custom domain, a
  publisher alias parent that matches the approved wildcard certificate scope
  now uses verified wildcard DNS. The first start can wait for that wildcard
  to be verified. Later publisher identities under the same parent do not
  need an exact DNS record. Existing publisher addresses, the shared service
  hostname, and bindings with exact certificates keep their existing records.
  An address can resolve without a live run; ingress does not serve it.
- Service DNS checks retry ordinary propagation at the normal poll interval.
  A real lookup error backs off based on consecutive errors for the current
  change, not on earlier runs or checks.
- When deleting an exact record beneath a wildcard, tnl verifies that its
  records and ownership marker are gone instead of waiting for the name to
  stop resolving.
- Bundled browser pages use the same favicon and styles as the website.

## Upgrade an existing server

This release advances PostgreSQL to schema `3`. A database on the supported
PostgreSQL v1 baseline can upgrade directly from rc.47. Client SQLite is
unchanged. Keep existing DNS records, grants, and storage keys.

1. Upgrade split ingress processes first. They can read the older control
   routing table and can enforce the wildcard deadline once control sends it.
2. Schedule a maintenance window. Stop old control or standalone processes and
   take a recoverable PostgreSQL backup with the matching storage key available
   separately. Use the new image's `tnld migrate` with
   `TNLD_DATABASE_DIRECT_URL`. Do not run an old control binary against the
   migrated database.
3. Start the new control or standalone processes using `TNLD_DATABASE_URL`.
   Verify a known public service returns the expected workload bytes. Use a
   fresh publisher identity to check the wildcard path; an identity that
   already has an exact address keeps it.

If control fails after migration, prefer a fix that can run against schema `3`.
To return to rc.47, restore the pre-upgrade backup with its matching storage
key before starting old control. A restore does not include any writes made
after the backup; account for them before choosing that recovery path.
